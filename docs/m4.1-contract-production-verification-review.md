## 验证目标

将 Consumer Contract 的约束从"设计文档中的约定"升级为"在代码/production 环境中可验证的 invariant"。

当前已有：
- 单元测试验证 Consumer 隔离（V-4）
- 单元测试验证 `evaluate()` 纯函数（B）
- 单元测试验证 Pipeline callback 路径（C）

缺少：
- 运行时验证：GuardrailConsumer 的 `onDecision callback` 生命周期不会被绕行
- 编译时约束：无类型层面的 way 阻止 Consumer 直接访问 RuntimeAction/Pipeline
- 错误路径覆盖：callback 断连、重复交付、traceId 不匹配的 Runtime 行为

## 验证项

### V-P1: Decision 唯一生产源

**Invariant:** `GuardrailDecision` 的唯一生产者是 `Policy.evaluate(input)`。

**检查方式：**

```typescript
// GuardrailDecision 类型的生产路径追踪
// 允许：GuardrailPolicy.evaluate()
// 禁止：Consumer 自行构建、Pipeline 合成、Runtime 注入
```

| 路径 | 是否允许 | 当前状态 |
|------|---------|---------|
| `GuardrailPolicy.evaluate(input)` | ✅ 唯一 | ✅ |
| `GuardrailProgressConsumer` 内部构建 Decision | ❌ | ✅ 未做 |
| `GuardrailPipeline` 直接合成 Decision | ❌ | ✅ 未做 |
| `ChatExecutor` 读取/合成 Decision | ❌ | ✅ 未做 |
| `ProgressAnalyzer` 产出 Decision | ❌ | ✅ M3 协议禁止 |

**验证方法：** 构建一个 test 矩阵，模拟以下场景并断言 Pipeline 不会产出非 Policy 来源的 Decision：

| Test | 场景 | 预期 |
|------|------|------|
| P-1a | Consumer 未投递 callback | Pipeline.check() → null |
| P-1b | Consumer 投递后 Pipeline 重置 | check() → null（latestDecision cleared） |
| P-1c | 非匹配 traceId 的 Decision | check() → null |
| P-1d | Consumer 投递 terminate → Pipeline 返回 TERMINATE | RuntimeAction === 'TERMINATE' |

### V-P2: Consumer 无 RuntimeAction 权限

**Invariant:** Consumer 不引用 `RuntimeAction` 或 `PipelineResult` 类型。

**检查方式：**

```typescript
// GuardrailProgressConsumer import 链检查
// 允许的 import：progress.ts, GuardrailTypes.ts (Decision/Policy/PolicyInput), GuardrailPolicy.ts
// 禁止的 import：GuardrailPipeline.ts, GuardrailTypes.ts (RuntimeAction), ChatExecutor
```

| import | GuardrailConsumer 当前 | 是否合规 |
|--------|----------------------|---------|
| `../progress` (ProgressSnapshot, ProgressConsumer) | ✅ | ✅ |
| `../GuardrailTypes` (GuardrailPolicy, GuardrailDecision, GuardrailPolicyConfig) | ✅ | ✅ |
| `../GuardrailTypes` (RuntimeAction) | ❌ | ✅ 未 import |
| `../GuardrailPolicy` (DefaultGuardrailPolicy) | ✅ | ✅ |
| `../GuardrailPipeline` | ❌ | ✅ 未 import |

**验证方法：** 静态检查 Consumer 文件的 import 链不包含 RuntimeAction 或 Pipeline 类型。

### V-P3: Callback 生命周期稳定

**Invariant:** `onDecision` callback 在 consume() 内部同步调用，且不依赖外部生命周期。

**当前验证：**

```typescript
// guardrail-consumer.test.ts
// - consume() 内同步调用 onDecision
// - 无论 consume 成功与否，callback 都被调用
// - callback 可选的：未提供时 no-op
```

**需补充验证：**

| Test | 场景 | 预期 |
|------|------|------|
| P-3a | Consumer 构造时未传 callback | consume() 不抛出异常 |
| P-3b | Consumer 构造时传 null callback | consume() 不抛出异常 |
| P-3c | consume() 中 policy.evaluate 出错 | callback 不被调用 |
| P-3d | callback 自身抛出异常 | consume() 不阻断其他 Consumer |

### V-P4: Error Path 明确

**Invariant:** Pipeline 所有路径都有明确定义的返回码，不会留下未处理的 Decision。

**当前行为：**

| 场景 | 返回 | 理由 |
|------|------|------|
| turn < minTurnsBeforeCheck | null | 未达到检查条件 |
| throttled | null | 间隔内 |
| 无 callback Decision | null | Consumer 尚未投递 |
| traceId 不匹配 | null | 跨 trace 污染 |
| 正常 callback Decision | PipelineResult | 包含 RuntimeAction + Decision |

**需补充验证：** Pipeline 返回 null 时，Runtime 不会错误地使用上一次的 Decision。

| Test | 场景 | 预期 |
|------|------|------|
| P-4a | check() 返回 null，但 previous check 返回过 TERMINATE | 不复用旧 Decision |
| P-4b | reset() 后 check() | 返回 null（latestDecision cleared） |
